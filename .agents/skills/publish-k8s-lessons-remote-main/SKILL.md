# 仅远程发布讲义到 main

## 目标

把 GitHub 远端 `main` 当成唯一事实来源。全程通过 GitHub 连接器或 API 读取和写入 `zz-datou/k8s_plat_gpu`，完成普通学习文档修改并核验远端结果。

## 固定边界

- 只对仓库 `zz-datou/k8s_plat_gpu` 应用本流程。
- 默认目标分支固定为 `main`，普通讲义修改直接提交，不默认创建分支或 Pull Request。
- 不对目标仓库执行本机 `git clone`、`git checkout`、`git pull`、`git commit` 或 `git push`。
- 不把本机工作区、本机缓存或先前记忆当成远端当前内容。
- 不强制更新分支，不覆盖并发修改，不静默改变用户没有要求的文件。
- 只把普通 Markdown 讲义、导航和仓库内教学 Skill 视为默认允许直接提交的低风险内容。

如果 GitHub 远程工具不可用或鉴权失败，说明阻碍并停止；不要自动退回本机 Git。

## 与源码讲义写作 Skill 配合

当任务涉及 Kubernetes 源码讲义的编写、重构或审校时，同时使用 `write-k8s-source-lessons`：

- 用 `write-k8s-source-lessons` 决定怎么讲、源码怎么核对、Go 语法怎么解释。
- 用本 Skill 决定怎样从远端读取、怎样安全写入 `main`、怎样验证提交结果。

本 Skill 只负责远程交付流程，不降低源码讲义的内容标准。

## 远程工作流

### 1. 锁定本次范围

从用户要求中确定目标章节、文件和改动目的。能够从仓库导航、文件名和上下文确定范围时直接继续；存在多个可能文件且不同选择会改变结果时，再向用户确认。

### 2. 读取远端基线

在任何写操作之前：

1. 读取远端 `main` 的最新提交 SHA。
2. 从 `main` 获取目标文件的完整内容和当前 blob SHA。
3. 新建文件时先确认路径确实不存在。
4. 记录准备提交时使用的父提交 SHA。

不要根据本机同名文件推断远端内容。用户在 GitHub 上看完后提出修改时，也要重新读取一次远端文件，因为它可能已经变化。

### 3. 形成最小改动

- 只修改用户要求的章节和必要导航。
- 保留远端文件里的其他新内容、格式和链接。
- 修改源码讲义时，从已锁定版本的 Kubernetes 上游源码重新核对关键路径、函数和语义。
- 不把未核验的本机副本整体覆盖到远端。
- 提交前检查 Markdown 标题层级、代码块、Mermaid 语法、相对链接和章节入口。

### 4. 选择写入方式

#### 单个已有文件

使用内容更新接口，明确指定：

- 仓库 `zz-datou/k8s_plat_gpu`
- 分支 `main`
- 远端刚读取到的 blob SHA
- 完整的新文件内容
- 能说明实际变化的提交信息

blob SHA 不匹配时，把它视为并发修改；重新读取并合并用户的新内容，不要强行覆盖。

#### 单个新文件

确认目标路径在 `main` 返回不存在后，使用远程新建文件接口直接写入 `main`。若路径已经出现，停止新建并按已有文件流程重新处理。

#### 多个彼此关联的文件

优先通过 GitHub Git Data 接口生成一个原子提交：

1. 重新取得 `main` 当前 HEAD 和该提交的基础 tree。
2. 为每个新内容创建 blob。
3. 以基础 tree 创建只包含本次路径变化的新 tree。
4. 以记录的 HEAD 为唯一父提交创建 commit。
5. 使用非强制方式把 `main` 更新到新 commit。

若 `main` 在步骤 1 之后前进，非快进更新应当失败。重新读取最新远端内容并判断如何合并；不要把 `force` 改为 `true`。

如果当前连接器无法安全完成原子多文件提交，先向用户说明限制。不要悄悄把一组必须同时生效的文件拆成中途可能不完整的多个提交。

### 5. 远端验证

写入后必须：

1. 重新读取远端 `main` 的最新提交。
2. 确认 `main` 已指向刚创建的提交。
3. 重新读取每个改动文件，确认内容来自新提交。
4. 检查提交中只有本次预期路径。

普通 Markdown 改动至少做静态检查。只有确实运行了远端 GitHub Actions，才可以声称测试或脚本已经执行；不要把本机临时校验说成仓库远端校验。

## 必须暂停的情况

遇到以下任一情况，停止写入并向用户说明：

- 文件 blob SHA 或 `main` HEAD 发生并发变化，且无法无歧义合并。
- 分支保护拒绝直接更新 `main`。
- 用户要求删除、批量改名、改 GitHub Actions、改权限、处理密钥或执行其他高风险仓库管理。
- 请求范围包含与讲义无关的代码或大量未知文件。
- 目标仓库不是 `zz-datou/k8s_plat_gpu`。
- GitHub 连接器不可用、权限不足或返回无法判断是否成功的结果。

未经用户同意，不要把策略改成操作本机 Git、强制更新、另建分支或发 Pull Request。

## 交付说明

完成后用简洁中文报告：

- 改了哪些远端文件。
- 主要修改是什么。
- `main` 的新提交 SHA 和可点击链接。
- 做了哪些远端核验，以及哪些测试没有运行。
- 若有阻碍，明确说明没有写入的原因和需要用户决定的事项。

## 典型触发语句

- “我在 GitHub 看完了，把第 13 章按我的意见改掉。”
- “全程远程操作，不要在我本机 pull 和 push。”
- “把新写的讲义和导航一起提交到原仓库 main。”
