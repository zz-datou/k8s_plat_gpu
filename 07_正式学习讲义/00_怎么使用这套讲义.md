# 使用约定：K8s 基础不重学，源码从生产问题进入

## 1. 先把你的水平定准

你的三个能力层级不同：

```text
Kubernetes 生产运维：
  已有多年平台/SRE经验，不按初学者重讲

Go 与 Kubernetes 源码：
  只读过少量章节，需要一步步建立调用链阅读能力

GPU Kubernetes：
  属于新的专项方向，需要从节点栈、调度和设备链系统学习
```

所以本课程的原则是：

> 默认你懂常规 Kubernetes 使用和生产现象；只在源码依赖某个精确定义时做快速校准。Go 语法和源码结构才按初学方式解释。

### 1.1 公司现场怎样进入课程

历史问题主要来自多地域、多环境的 Java 业务 Kubernetes 平台：GitLab CI、Kustomize、Argo CD、EKS/ACK、Ingress/ALB/MSE/Nginx、配置中心和监控探针。GPU 是下一阶段能力，不能把教学演练写成已经发生过的公司事故。

配套的 [企业实战案例库](案例库/README.md) 使用三类标记：`A` 真实故障抽象、`B` 多事故合成、`C` 迁移演练。域名、IP、集群 ID、账号、镜像 tag 和凭据全部使用占位符。

多集群环境中的所有实验统一遵守：

1. 命令显式写 `--context` 和 `-n`，先核对 cluster / namespace UID。
2. 先保存 Git revision、渲染结果和 live 快照，再做写操作。
3. 优先在随机命名、带 owner label 的实验 namespace 执行；清理前再次核对 namespace UID。
4. 生产动作必须有停止条件、回滚点和修复后业务验收。
5. 工具失败、权限不足和未执行都要如实记录，不能写成“结果为空”或“已经通过”。

## 3. 源码课固定怎样讲

每篇源码课按这个顺序：

```text
真实生产现象
  -> kubectl / status / Event / 日志证据
  -> 哪个组件消费这些状态
  -> 精确文件、函数和关键代码块
  -> 关键 if / 公式为什么这样判断
  -> Go 语法现场补充
  -> 回到生产排障
  -> 映射到 GPU 场景
```

不会采用：

- 从目录第一行开始通读；
- 一次塞入几十个内部函数；
- 为讲 Go 而脱离 Kubernetes 单独铺很久；
- 让你背固定行号；
- 把旧的 `01~1267` 当必读清单。

## 4. 源码深度怎么分

| 深度 | 要求 |
|---|---|
| S0 | 不读源码，生产配置、兼容和故障处理学深 |
| S1 | 认识组件边界与关键入口 |
| S2 | 读一条精选调用链，能解释关键判断 |
| S3 | 读穿核心状态流、失败流和重试流，能从生产证据反查源码 |

你的重点：

```text
Deployment 源码热身：S2
scheduler：S3
kubelet / CRI：S3
Device Plugin / DeviceManager：S3
NVIDIA Driver / CUDA / Toolkit：运维深，源码 S0
GPU Operator / DCGM / vLLM：S0~S1，做二开时再升级
```

## 5. Go 怎么补

不先单独学完一整本 Go。

遇到下面内容时现场解释：

- receiver 和指针；
- slice、map 和 range；
- 多返回值与 `if err != nil`；
- interface；
- context；
- goroutine、channel 和锁；
- defer；
- workqueue 泛型。

每次只解释当前代码真正用到的部分，并马上翻译成控制器行为。

## 6. 一篇源码课怎样算通过

不是“看完”就算。至少做到：

1. 能从一个生产现象找出对应 status/Event。
2. 能在本地源码定位关键入口和核心判断。
3. 能用自己的话解释“为什么这个 if 会导致当前现象”。
4. 能说出相同机制怎样影响 GPU 工作负载。
